Smart PPE Compliance Detection System

B.Tech Final Year Artificial Intelligence & Machine Learning Project Documentation & Viva Voce Guide

1. Project Abstract & Objective

Workplace accidents in high-hazard industrial environments (construction sites, manufacturing facilities, chemical plants) are frequently caused by workers failing to wear mandatory Personal Protective Equipment (PPE). This project implements an end-to-end, edge-ready computer vision system that monitors video streams in real-time, detects whether workers are wearing mandatory safety equipment (Hard Hats / Safety Helmets and High-Visibility Reflective Vests), associates items with individual workers using spatial anatomical matching, generates audit-ready violation evidence, and interfaces with microcontroller hardware (ESP32) to actuate physical alarm lights and buzzers.

3. Spatial Association Algorithm (Avoiding Cross-Worker Assignment)

A common failure mode in naive multi-object detection is misassigning one worker's helmet to an adjacent worker. Our spatial matching algorithm enforces anatomical containment:

$$\text{Head Region: } [x_1, y_1 - 0.05 \cdot H, x_2, y_1 + 0.38 \cdot H]$$ $$\text{Torso Region: } [x_1, y_1 + 0.20 \cdot H, x_2, y_1 + 0.78 \cdot H]$$ $$\text{Intersection Ratio (IoB)} = \frac{\text{Area}(\text{PPE Box} \cap \text{Anatomical Region})}{\text{Area}(\text{PPE Box})} \ge 0.30$$

If a person is truncated (head clipped above frame boundary) or too small, the system safely classifies the state as NEEDS_REVIEW rather than generating false violation accusations.

4. ESP32 Microcontroller Integration & Arduino Code

The software communicates over USB Serial at 115,200 baud. Connect the following components to your ESP32:

  • Green LED: GPIO 18 (with 220Ω resistor) → Safe / Compliant status
  • Red LED: GPIO 19 (with 220Ω resistor) → Violation alert
  • Active Buzzer: GPIO 21 → Audible warning tone
  • Ground (GND): Common ground rail
Arduino C++ Sketch (esp32_ppe_alarm.ino):
// ESP32 Smart PPE Compliance Hardware Controller
const int PIN_GREEN = 18;
const int PIN_RED = 19;
const int PIN_BUZZER = 21;

void setup() {
  Serial.begin(115200);
  pinMode(PIN_GREEN, OUTPUT);
  pinMode(PIN_RED, OUTPUT);
  pinMode(PIN_BUZZER, OUTPUT);
  
  // Power-on self test: flash LEDs
  digitalWrite(PIN_GREEN, HIGH);
  delay(200);
  digitalWrite(PIN_GREEN, LOW);
  digitalWrite(PIN_RED, HIGH);
  delay(200);
  digitalWrite(PIN_RED, LOW);
}

void loop() {
  if (Serial.available()) {
    String command = Serial.readStringUntil('\n');
    command.trim();
    
    if (command == "STATE:COMPLIANT") {
      digitalWrite(PIN_GREEN, HIGH);
      digitalWrite(PIN_RED, LOW);
      digitalWrite(PIN_BUZZER, LOW);
    } 
    else if (command.startsWith("STATE:VIOLATION")) {
      digitalWrite(PIN_GREEN, LOW);
      digitalWrite(PIN_RED, HIGH);
      // Staccato alarm beep
      digitalWrite(PIN_BUZZER, HIGH);
      delay(150);
      digitalWrite(PIN_BUZZER, LOW);
    } 
    else {
      // Idle / Standby
      digitalWrite(PIN_GREEN, LOW);
      digitalWrite(PIN_RED, LOW);
      digitalWrite(PIN_BUZZER, LOW);
    }
  }
}

5. B.Tech Viva Voce Questions & Model Answers

Q1: Why can't standard COCO-trained YOLO models be used for PPE compliance detection?
Answer: The standard Microsoft COCO dataset only contains 80 generic classes (e.g. "person", "car", "dog"). It does NOT include specialized industrial PPE classes such as "helmet", "hard_hat", "safety_vest", or explicit "no_helmet" labels. Claiming a COCO model detects PPE is technically incorrect. A custom or fine-tuned YOLO model trained on construction safety datasets (e.g., Pictor-v3, SHWD, or Roboflow PPE datasets) is mandatory.
Q2: How does the system handle continuous video streams without filling disk space with redundant violation photos?
Answer: An anti-flooding cooldown manager (EvidenceManager) enforces a configurable cooldown window (default 5.0 seconds) per violation category. If a worker continuously stands without a helmet for 60 seconds, only 1 snapshot is captured every 5 seconds rather than generating 1,800 duplicate images (30 FPS × 60s).
Q3: What evaluation metrics are used to measure PPE detector performance?
Answer: We evaluate using Precision ($P = \frac{TP}{TP + FP}$), Recall ($R = \frac{TP}{TP + FN}$), and mean Average Precision (mAP@0.5 and mAP@0.5:0.95) across all bounding boxes. In safety systems, higher Recall for the "no_helmet" / "no_vest" class is prioritized to minimize False Negatives (unreported violations).
Q4: Why is SQLite chosen instead of complex client-server databases for this edge prototype?
Answer: SQLite is serverless, zero-configuration, and stores the entire audit database in a single portable file (ppe_violations.db). It provides full ACID transaction guarantees without needing an external background daemon, making it optimal for local Windows deployments and edge microcomputers (e.g. Raspberry Pi / Jetson).
